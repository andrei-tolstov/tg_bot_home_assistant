# Извлеченные уроки и правила

1. **Таймауты в HTTP-клиентах**: Всегда явно задавать таймаут (5 секунд). Значения по умолчанию приводят к долгому "зависанию" асинхронных хэндлеров Telegram при недоступности внешних серверов.
2. **Логирование вместо print на Windows**: Использовать модуль `log` / `logging`, избегать сырых вызовов `print()` с не-ASCII строками (кириллицей), так как в кодировках cp1251/cp1252 это может приводить к ошибкам кодировки.
3. **Информативная обратная связь**: При вызове внешних API возвращать понятное описание ошибки, чтобы пользователь в чате Telegram сразу видел, в чём проблема (таймаут, неверный токен 401, неверный IP и т.д.).
4. **Обработка TelegramBadRequest**: При редактировании сообщений или инлайн-клавиатур подавлять ТОЛЬКО `"message is not modified"`, а остальные ошибки логировать, чтобы не маскировать ошибки синтаксиса или лимитов.
5. **Лимит на callback_data (64 байта)**: В Telegram длина `callback_data` у инлайн-кнопок строго ограничена 64 байтами. Использовать ультра-короткие префиксы (например, `dt:`, `dv:`, `t:`), чтобы длинные `entity_id` (например, длинные имена автоматизаций) не приводили к отклонению клавиатуры сервером Telegram.
6. **HTML вместо Markdown**: Использовать `parse_mode="HTML"` с экранированием `html.EscapeString()`. Markdown в Telegram ломается от символов `_`, `*`, `[` в технических идентификаторах (вроде `switch.relay_1` или `automation.auto_light`).
7. **Работа со строками UTF-8 в Go**: При обрезке строк (например, названий кнопок до 20 символов) всегда конвертировать строку в `[]rune`, так как кириллические символы занимают 2 байта, и срез по байтам `s[:18]` ломает символ UTF-8.
8. **Структура ReplyKeyboardMarkup в go-telegram-bot-api v5**: В библиотеке `v5.5.1` поле `ResizeKeyboard` и `InputFieldPlaceholder` поддерживаются из коробки.
9. **Один экземпляр getUpdates (HTTP 409 Conflict)**: Telegram не позволяет параллельно опрашивать `getUpdates` двум процессам с одним токеном. При запуске второго экземпляра старый опрос сбрасывается (`terminated by other getUpdates request`), что блокирует доставку обновлений.
10. **Асинхронная обработка и защита от паник в Go**: Обрабатывать входящие апдейты в горутинах (`go safeHandleUpdate(update)`) с `recover()`, чтобы тяжелые запросы или ошибки в одном сообщении не блокировали очередь опроса Long Polling.
11. **Покрытие доменов устройств Home Assistant**: Осушители и увлажнители воздуха в Home Assistant находятся в домене `humidifier` (со стандартным сервисом `humidifier.toggle`). Для полноценного управления домом список `ControllableDomains`, `DomainIcons` и `DomainNames` должен обязательно включать `humidifier`, а также другие управляемые домены (`water_heater`, `valve`, `siren`).
12. **Ограничения рендеринга инлайн-кнопок Telegram**: Клиенты Telegram (Desktop/Mobile) рендерят `InlineKeyboardButton` строго в одну строку (`nowrap`) и игнорируют `\n`, обрезая длинный текст многоточием при 2 колонках. Для предотвращения обрезки длинных названий (> 18 символов) необходимо использовать адаптивную сетку: длинные кнопки выносить в отдельный ряд на 100% ширины экрана, а короткие группировать по 2.
13. **Лимит размера инлайн-клавиатуры Telegram (10 КБ) и пагинация**: При большом количестве сущностей (например, 78 устройств) отправка всех кнопок в одной клавиатуре вызывает ошибку Telegram API `Bad Request: reply markup is too long`. Для списков устройств и категорий с большим количеством элементов обязательна пагинация (по 10 устройств на страницу) с навигационными кнопками `⬅️ Назад`, `Стр. X/Y`, `Вперед ➡️` и сохранением текущей страницы при переключении состояния.
14. **Фильтрация пустых категорий (count == 0)**: Категории устройств, в которых нет активных подключенных сущностей (`len(items) == 0`), должны автоматически скрываться из меню категорий (`GetDomainsKeyboard` и `showDomainsMenu`), чтобы не засорять интерфейс неактивными кнопками.
15. **Коллизия имен бинарника и директорий в Dockerfile**: Не использовать в `go build -o /app/<name>` имя, совпадающее с существующей директорией пакета (например, `/app/bot` при наличии папки `bot/`), так как Docker скопирует директорию вместо исполняемого файла, что приведет к ошибке `exec: "/app/bot": is a directory: permission denied`. Собирать исполняемый файл в системные пути (например, `/usr/local/bin/tg-bot`).
16. **Категории сущностей в Home Assistant (Entity Registry через WebSocket)**: Движок шаблонов Jinja2 в REST API Home Assistant (`/api/template`) не содержит функции `entity_category` и блокирует вызовы мутации списков (`list.append`) по соображениям безопасности. Для получения категорий сущностей (`config`, `diagnostic`), признаков скрытости (`hidden_by`) и привязки к устройствам (`device_id`, `device_name`) необходимо использовать WebSocket API Home Assistant (`config/entity_registry/list` и `config/device_registry/list`), комбинируя их с оперативными состояниями из `/api/states`.
17. **Таймаут Telegram Bot API клиента при Long Polling**: Библиотека `go-telegram-bot-api` по умолчанию использует `http.DefaultClient` без таймаута (`Timeout: 0`). При разрыве TCP-соединения (`unexpected EOF`) без закрытия сокета соединение зависает в TCP retransmission, блокируя получение новых сообщений насовсем. Для инициализации бота всегда использовать `tgbotapi.NewBotAPIWithClient` с `httpClient`, где `Timeout` превышает таймаут Long Polling (например, 45 секунд при polling timeout 30 секунд).
18. **Приоритет имен сущностей в Home Assistant (Entity Registry vs YAML)**: Если сущность имеет `unique_id`, ее имя в Home Assistant определяется записью в `core.entity_registry` (или UI), которая переопределяет директиву `name` из YAML-конфигурации (`configuration.yaml`). Поэтому сущность может отображаться в Telegram-боте под старым именем из реестра (например, «Комп» вместо «CompSwitch»).
19. **Разделение идентификатора сущности и домена в callback-хэндлерах**: При обработке переключения сущностей внутри категории (`dt:`) идентификатор сущности (`entityID` или хэш `ref`) никогда не должен передаваться в методы отображения категорий вместо имени домена (`domain`). Домен должен надежно извлекаться из `entityID` (`entityID[:dotIdx]`). Ответ на `CallbackQuery` (`AnswerCallbackQuery`) необходимо отправлять строго после выполнения команды переключения, отображая реальный статус операции (`🟢 ВКЛ` / `⚪ ВЫКЛ`) или алерт ошибки, а не преждевременно с заглушкой «Переключаю...», блокирующей показ результата.

20. **Группировка только управляемых сущностей устройства (Device Grouping)**: При объединении сущностей одного физического устройства (`DeviceID`) группировать только управляемые домены (`IsControllableDomain`). Автономные датчики без органов управления (например, комбинированный датчик температуры и влажности) не должны схлопываться между собой, чтобы пользователь продолжал видеть оперативные показания каждого датчика в списке.
21. **Очистка префиксов устройств на инлайн-кнопках реле (`FormatChildEntityName`)**: В Home Assistant имена дочерних сущностей часто формируются как `"<DeviceName> <SubEntityName>"`. Внутри карточки конкретного устройства префикс названия устройства избыточен. Очистка префикса делает текст на кнопках кратким и предотвращает обрезку строк многоточием клиентами Telegram.
